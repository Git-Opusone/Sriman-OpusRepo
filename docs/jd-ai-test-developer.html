About the Role

Opus One is a live, enterprise-grade AI platform that automates property record searches across every US county. The core engine is built — now we need a sharp, curious developer to systematically validate it county by county, surface edge cases, and drive code fixes using Claude Code as the AI pair-programmer.

This is not a traditional QA role. You will read code, run searches, interpret AI agent output, raise issues, and fix them — all guided by Claude Code. It is an ideal first role for a Java/AI trainee who wants to grow fast inside a production AI system.

🎯
What You'll Do — Day to Day
  • 1 County-by-county validation — Work through US counties systematically. For each county, run searches using Name, Account Number, and Parcel ID use cases. Document pass / fail / partial results in the Staging Test Tracker.
  • 2 Use case testing — Test every combination the platform supports: first name only, last name only, full name, account number, parcel ID — and edge cases like hyphenated names, numeric-only IDs, and special characters.
  • 3 Platform handler verification — Verify that each of the 8 AI agent handlers (Tyler, Vision, Beacon, QPublic, BIS, Patriot, PublicPortal, Anderson Tax) behaves correctly for counties assigned to it. Flag platform detection mismatches.
  • 4 AI-assisted debugging — When a county fails, use Claude Code to diagnose the issue, understand the handler code, propose a fix, and apply it. You are not expected to fix everything manually — you are expected to drive Claude Code to do it correctly.
  • 5 Result quality review — Validate extracted data (owner name, parcel ID, property address, tax amounts, payment status) against what the county website actually shows. Flag data accuracy issues separately from search failures.
  • 6 Log & metrics monitoring — Check the Grafana Live Dashboard daily. Identify error spikes, CAPTCHA blocks, or latency anomalies. Correlate log entries with test results to understand root causes.
  • 7 Test tracker maintenance — Keep the Staging Test Tracker updated with every county tested, result status, issue details, and fix applied. This is the source of truth for platform coverage.
  • 8 CI/CD awareness — Push fixes through the GitHub Actions pipeline. Verify deployments succeed. Understand the Docker + EC2 deployment flow well enough to confirm your fix is live in production.
☀️
A Typical Day in This Role
Morning

Check Grafana dashboard for overnight errors. Review CI/CD pipeline status. Pick 3–5 counties from the test tracker queue and run full use-case sweeps.

Midday

Deep-dive on any failed county — open Claude Code, paste the failure log, walk through the handler code, identify the fix, apply it, and push via GitHub Actions.

Afternoon

Update the Staging Test Tracker with results. Verify the fix is live on opusone-ai.orchestrate.com. Re-run the failed county to confirm resolution. Document what you learned.
