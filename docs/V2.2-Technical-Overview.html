Platform Overview

Executive summary, version milestones, and what V3.0 adds

Orchestrate-Mortgage is a fully automated Agentic AI platform for US mortgage property tax and title research. The system uses a hierarchy of AI agents, each backed by deterministic platform-specific handlers (Robos), to search county assessor and tax office websites and return structured property records. V3.0 adds complete Texas Tax Office coverage: 254 counties, 9 Tax Office handlers, sequential CAD→Tax Office dual-search, and a three-tier CAPTCHA resolution system with CapSolver integration.

Development Journey — 12 Steps

From single-county proof of concept to full Texas Tax Office dual-search with tiered CAPTCHA
1

AI Model Research & Selection (GPT-4o-mini)

Evaluated multiple LLMs for browser automation with vision capabilities. GPT-4o-mini selected for its balance of vision quality, tool-calling reliability, and cost. Groq trialed for speed but lacked reliable vision output for complex county site layouts.

2

Core Agent Built (netronline.com, 3,000+ counties)

Core agent built using GPT-4o-mini + Playwright. Agent receives owner name or parcel ID, takes screenshots, reads form labels, fills fields, and extracts results. netronline.com identified as the authoritative US county assessor URL directory.

3

Search Engine Proved (Andrews County TX)

First end-to-end validation: agent navigated Andrews County TX CAD site, entered owner name, extracted parcel data including owner, address, assessed value, and legal description. Confirmed the full AI-driven approach works without hard-coded selectors.

4

50 State Sub-Agents Created

Master agent spawned one sub-agent per US state. Each sub-agent received its state's netronline.com listing page and crawled every county entry, extracting the assessor URL and county name. Core agent coordinated and merged all results.

5

Scale: 50 × 3,000 × 7 = 21,000+ URLs

Across 50 states, ~3,200 counties, each with up to 7 URL variants (primary assessor, alternate search paths, etc.), the data/counties.json file grew to 21,000+ URL entries. Platform labels (qpublic, tyler, beacon, patriot, vision, bis, generic) were assigned per entry via platformDetector.js.

6

Platform Handlers Built (6 Robos)

Six deterministic Playwright handlers built for the dominant county assessor platforms: qpublic.js, tyler.js, beacon.js, patriot.js, vision.js, bis.js. Each handler knows the exact form structure, Angular timing requirements, session quirks, and extraction patterns for its platform.

7

Core + Sub-Agents + Handlers = 21,000 URLs Covered

platformDetector.js routes each search to the correct handler by URL pattern and HTML fingerprint. Handler success rate >95% on recognized platforms. GPT-4o-mini AI fallback retained for unrecognized platforms and handler failures.

8

CAPTCHA & Access Control Handled (8.1–8.6)

  • 8.1 US-region EC2 deployment (us-west-2 Oregon) for county IP whitelists
  • 8.2 Cloudflare: playwright-extra + puppeteer-extra-plugin-stealth spoofs fingerprints
  • 8.3 Concurrency: MAX_CONCURRENT_SEARCHES=3 gate prevents browser overload
  • 8.4 Per-search timeout: SEARCH_TIMEOUT_MS=180000 (3 min), returns 504 on expiry
  • 8.5 SSL: self-signed certificates supported via --ignore-certificate-errors
  • 8.6 Tyler session handling hardened; CAPTCHA detect-and-flag across all handlers
9

Search → Scrape → Extract → SSE Results

Full pipeline hardened: SSE stream sends status, progress, captcha, results, and done events. LRU cache (4hr TTL, 1000 entries max) returns cached hits in <5ms. resolveCountyUrl() performs URL health check and refreshes from netronline if the stored URL is dead.

10

Store in DB → Reports

Search results stored to database with metadata (county, state, search type, timestamp, handler used). Report generation pipeline produces structured output for mortgage file review. Grafana Alloy + Loki + Prometheus monitoring stack deployed on EC2.

11

TX Tax Office Dual-Search Integration

Problem: For Texas, the CAD (County Appraisal District) gives property assessment data but NOT tax bills. Tax bills come from a separate Tax Office system with different URLs, different databases, and different search methods.

Solution: Sequential dual-search — CAD runs first, extracts cadAccountNumber and cadOwnerLastName, then the Tax Office handler runs using those extracted values as search inputs.

  • New endpoint: POST /api/tax/search/multi/stream (Server-Sent Events)
  • 254 TX counties mapped: each gets taxUrl + taxPlatform in counties.json
  • 9 new Tax Office platform handlers: propertytaxpayments (191 counties), actweb (17), txcountytax (9), taxweb (4), go2gov (2), andersontax (1), ptaxpro, publicportal, bis
  • actweb specifics: TX parcel IDs ARE CAD Reference Numbers; 4-strategy search (cadRef → account → fullName → lastName); radio button detection by label text; showdetail2.jsp text-regex extraction
  • extractTaxAccountId() checks additionalDetails first (taxOfficeRef > refId > geoId > propId), then parcelId
12

Tiered CAPTCHA Resolution + CapSolver Integration

Problem: After deploying the propertytaxpayments.net handler for 191 TX counties, Cloudflare challenges began blocking searches on high-traffic query sequences.

Solution: 3-tier CAPTCHA system —

  • Tier 1 (Free): Cloudflare JS challenge: wait 25s for Chromium to auto-pass. Turnstile: wait 6s, then click iframe checkbox. ~90%+ resolution rate at $0 cost.
  • Tier 2 (Paid, last resort): CapSolver REST API — AntiTurnstileTaskProxyLess, polls every 3s up to 120s, token injected into page. Only triggered when Tier-1 fails AND CAPSOLVER_API_KEY is set.
  • Blocked (no solve): reCAPTCHA, hCaptcha, generic challenges → captchaBlocked immediately. No CapSolver credit spent.

New files: captchaSolver.js (CapSolver via Node https module — capsolver-npm had broken dist/), captchaDetector.js rewritten with tier logic. New env var: CAPSOLVER_API_KEY. Balance check: GET /api/tax/capsolver/balance.

Agent Architecture

Master AI agent, 50 state sub-agents, and how nationwide county data was bootstrapped at scale

The core insight: the same AI agent that learned to search one county could be instructed to discover all counties. Instead of manually curating 3,200+ URLs, the master agent was pointed at netronline.com and let it spawn sub-agents for each state. Each sub-agent applied the same "crawl, identify, extract URL" playbook across every county in its state.

🤖
Master AI Agent
GPT-4o-mini · Vision + Tool Calling · Playwright
Task 1 — Source Identification Identify netronline.com as the authoritative US county assessor directory. Learn the site structure: state index pages, county listing pages, external assessor URL links.
Task 2 — Spawn 50 State Sub-Agents For each of the 50 US states: spawn a sub-agent assigned to that state's netronline page. Sub-agent crawls each county entry, extracts the assessor/CAD URL, and flags the county name.
Task 3 — Platform Classification (platformDetector.js) Each extracted URL is passed through platformDetector.detectFromUrl() to classify into: qpublic, tyler, beacon, patriot, vision, bis, or generic. This label is stored alongside the URL.
Task 4 — Data Consolidation (data/counties.json) All sub-agent results are merged into data/counties.json: one record per county with state, county name, assessor URL, platform key. TX counties also receive taxUrl + taxPlatform fields. Live URL health checks flag dead links for netronline refresh.

Texas Tax Office Dual-Search

Why TX needs two searches, how extractTaxAccountId() works, and full platform coverage table

Part A — The Problem

Texas constitutionally separates property appraisal from tax collection. The same property exists in two separate databases:

CAD — County Appraisal District

  • Owner name and address
  • Parcel ID / account number
  • Assessed market value
  • Legal description / acreage
  • Exemption status

Tax Office — Separate System

  • Tax levy (amount billed)
  • Current year amount due
  • Prior year amount due
  • Total amount due
  • Last payment date/amount

Part B — The Solution: Sequential Search & extractTaxAccountId()

extractTaxAccountId() Priority Chain

1
additionalDetails.taxOfficeRef — highest priority
2
additionalDetails.refId
3
additionalDetails.geoId
4
additionalDetails.propId
5
Common key patterns (id, acctNum, parcelId, etc.)
6
Top-level parcelId — last resort

actweb 4-Strategy Search Flow

1

cadref search

Search by CAD reference number (account number from CAD result). TX parcel IDs ARE CAD Reference Numbers on actweb.

2

account search

Search by account number directly. Radio button detected by label text (not hard-coded selector).

3

Full cleaned owner name

cleanNameForActweb(): strip &, normalize spaces, uppercase. Full name search on showdetail2.jsp.

4

Last name only

First word of owner name used as last name fallback. Text-regex extraction for tax levy/due/value fields.

CAPTCHA & Access Control — Tiered Resolution

Three-tier system: free self-solve, CapSolver paid, and blocked-no-solve categories
Tier 1 — Free Self-Solve

captchaDetector.js (Rewritten)

  • Cloudflare JS Challenge: Real Chromium auto-passes the JS challenge. Wait up to 25s polling every 2.5s. Cost: $0.
  • Cloudflare Turnstile: Wait 6s (managed Turnstile auto-approves). If still pending: find challenges.cloudflare.com iframe, click input[type="checkbox"]. Wait 4s. Cost: $0.

~90%+ of Cloudflare challenges resolved free at Tier 1.

Tier 2 — CapSolver Paid (Last Resort)

captchaSolver.js (New)

  • Only triggered if: Tier-1 exhausted AND CAPSOLVER_API_KEY env var set AND type is Cloudflare
  • Uses direct Node.js https module (not npm package — capsolver-npm had broken dist/)
  • solveTurnstile(page): extract sitekey from DOM/HTML, call AntiTurnstileTaskProxyLess, poll every 3s up to 120s
  • Token injected via textarea value, data-callback, global __cfTurnstileToken
  • Balance endpoint: GET /api/tax/capsolver/balance

Per-solve CapSolver credit; only burned when Tier-1 fails.

Blocked — No Solve Attempted

Unsolvable CAPTCHA Types

  • reCAPTCHA v2 / v3: Google's checkbox and invisible challenge → captchaBlocked immediately
  • hCaptcha: hcaptcha.com iframe → captchaBlocked immediately
  • Generic challenges: "verify you are human" blocking overlays → captchaBlocked immediately

No CapSolver credit spent on unsolvable types.

Other Access Control Measures

ControlImplementationValue
IP Validation (8.1) AWS EC2 us-west-2 (Oregon) deployment Passes county IP whitelists; avoids non-US IPv6 blocks
Cloudflare Detection (8.2) playwright-extra + puppeteer-extra-plugin-stealth Spoofs WebGL, navigator.webdriver, canvas fingerprints
